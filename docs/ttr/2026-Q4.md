# 2026 Q4: time to rewrite

How long would a fully automated, hands-off rewrite of Badi take one
engineer driving agents?

**About two quarters, roughly 4–7 months.** The engineer remains the
oracle wherever a runner cannot see the product, so a rewrite that lands
only when an outside check says the behavior survived has no finish time
yet. The checkout is about fifty thousand lines of product source with
the test files set aside, and drafting it is the short part. The engine
suites, Fcitx ctests, QML lifecycle and Lab page tests sit beside the
code they describe, so a module and its tests can go green together.
Grey text, an edit the app holds, a revision read back, the bar and the
model gates sit past those suites. Freezing the oracles CI already runs
is on the order of **6–10 weeks**. The months after that are a Hyprland
seat, which no runner has.

## What each surface can prove

**Broker.** The Rust 1.99 job runs `cargo test --workspace --all-features
--locked`: framing, policy, binding, and `broker/src/engine/tests/`
(commit, type-through, spelling, revision, alternatives, desktop holds,
rejections). `--provider phrase` is the fixture. The installed-model
probe, `cargo test --release --locked --test writing_runtime -- --ignored`,
stays out of the workflow because CI never passes `--ignored`. The
external check is the phrase-broker drives in the
[verification map](../../.cursor/skills/verify-badi/features/README.md),
and no job runs them.

**Fcitx.** `npm run fcitx5:check` builds the addon and runs keys,
type-through, one-shot commit, foreign-IME yield and the revision core.
`npm run fcitx5:integration` and `adapters/fcitx5/tests/broker-smoke.py`
put the C++ transport on a real broker. The Fcitx job also runs
`adapters/fcitx5/tests/observed-desktop.py` (real addon, private bus,
synthetic observer). The
[runbook](../../adapters/fcitx5/README.md#build-and-test) records that
pass as transport and state. `commitString` is `dispatched-unverified`.
Grey pixels, a physical key and an applied edit stay a live trial.

**Obsidian.** `npm run editors:check` runs `adapters/obsidian/main.test.mjs`
against a scripted client: accept, undo, alternatives, a spelling
suffix, focus refusal. `node adapters/obsidian/live.mjs --headless
--local` drives the installed app in a temporary vault. Its pass list
is eight checks: display, the 800 ms reading window, Tab, Ctrl+Right,
native undo, Escape, a stale caret, restart recovery. No job installs
Obsidian or runs that file.

**Neovim.** `plugin.test.mjs` and `broker.test.mjs` drive `nvim
--server`: inline text, Tab, Ctrl+Right, one-step undo, alternative
picks, a real phrase broker. Repository checks skip them, because
Ubuntu's Neovim predates inline virtual text. `Neovim plugin / pinned
Arch` sets `BADI_REQUIRE_NEOVIM=1`. A foot or Ghostty chord stays in
the [tested-with matrix](../../adapters/neovim/README.md#tested-with).
The plugin does not negotiate spelling replacement.

**Bash.** `npm run shell:check` (via `editors:check`) runs
`adapters/shell/test-preview.py`: a PTY, a controlled bridge, grey ANSI,
spelling replacement, undo, nothing submitted. `adapters/shell/test.py`
is that PTY against a phrase broker. The Rust job builds
`badi-preview.so` and runs `adapters/shared/broker-client.test.mjs`,
and leaves `test.py` unrun. `drive word-suggestion` and `drive spelling`
check the bridge insert and a counter. No job runs them.

**Writer.** `npm run libreoffice:integration` is the pinned-Arch job: a
phrase broker, `soffice --headless`, a private UNO pipe, the paragraph
read back, one undo step, stale edits, and `teh` left alone because the
fixture corrects only an unambiguous word. `npm run libreoffice:check`,
which `npm run check` runs, is the source contract. The Wayland window
and a model choice among several candidates are the remainder.

**Omarchy panel.** `npm run omarchy:check` is ShellCheck, the source
contracts, the keyboard and statistics models, and, when `qs` is
present, the offscreen QML lifecycle. CI's `check-host.sh` runs that
against Omarchy `8d19ad75` with the official validator, host hashes and
`qmllint`, talking to a fake `badictl`. The
[runbook](../../ui/omarchy-plugin/README.md#checks) calls these source
and process contracts. The
[panel journey](../../.cursor/skills/verify-badi/features/omarchy-panel.md)
is a click and a screenshot. A green `omarchy:check` leaves `panel-open`
unproven.

**Prediction Lab.** `npm run writing:check` and the workspace test of
`badi-writing-lab` cover the page, the worker, qualification
bookkeeping and device inspection. They load no pinned model.
`--inspect-device` describes the machine and stores no draft. A quality
claim is two runs of the same suites, settings and seed, scored on the
gates in [model selection](../../docs/architecture/model-selection.md#stages-and-gates):
complete-word p95 at most 550 ms, at least 40 confirmation cases per
language, at least 60% useful on-time full additions, zero harmful.
That pair is a manual step when inference changes.

**Spelling.** `broker/src/spelling/tests.rs` and
`broker/src/engine/tests/spelling.rs` bind a replacement to the original
suffix, refuse an unbound or spacing change, and keep append-only apps
and Writer apart. `drive spelling` checks `adress` to `address` on the
Bash bridge. Writer's integration reads the paragraph back. An
append-only correction is a delete, a commit and a read-back
([ADR 0011](../../docs/decisions/0011-checked-corrections-in-append-only-apps.md)).
`correction_confirmed` is a live field.

**Revision.** `broker/src/engine/tests/revision.rs` covers one apply, a
second synonym, Escape, refusals, the one-line span and expiry.
`observed-desktop.py` applies a revision once when Tab is pressed again.
The [feature file](../../.cursor/skills/verify-badi/features/selection-revision.md)
records no headless driver: the harness never selects text, though
`--provider phrase` installs `FixtureReviser`. Candidate strikethrough,
`revision_confirmed` after a read-back, and a password field with no
`revision.request` are a desktop trial. Obsidian, Neovim and Writer
leave selection revision to the Fcitx path.

**CI.** [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) runs
nine jobs: Rust 1.99, MSRV 1.85, the Omarchy plugin, the AUR package,
Debian 13 and Ubuntu 24.04 packages, Fcitx, Neovim, LibreOffice, and
repository checks (`npm run check`, whitespace, shellcheck). Absent
from every job: the six verify-badi drives, `adapters/shell/test.py`,
`adapters/obsidian/live.mjs`, `writing_runtime` under `--ignored`, a
paired Lab comparison, and any Hyprland seat.

## Gaps, by how much they would cut the time

1. **Read the field back on the Fcitx path.** Extend
   `observed-desktop.py` so the synthetic field equals the committed
   suggestion, and an ADR 0011 correction records `correction_confirmed`
   where the lane stops at `dispatched-unverified`. That covers the
   primary surface and append-only spelling, and it is the largest cut.

2. **Drive revision on `FixtureReviser`.** Add `verify-badi.sh drive
   revision`: select a known string, cycle grammar, refine and synonym,
   apply once, require the read-back, check that Escape leaves the text,
   and check that a password field sends no `revision.request`. The
   engine tests travel with a rewrite of `engine/revision.rs`; this
   drive stays outside that crate.

3. **Gate one paired Lab comparison.** Run the catalog model on one
   frozen suite, settings and seed, twice, and fail when the pair misses
   the published gates (p95 at most 550 ms, at least 60% useful on-time
   full additions, zero harmful). Promote the ignored `writing_runtime`
   probe into that job.

4. **Run the oracles already written.** One job for `verify-badi.sh`
   (`launch`, `doctor`, the six drives) and `adapters/shell/test.py`
   against that broker, and one that installs Obsidian and runs
   `node adapters/obsidian/live.mjs --headless --local`, requiring
   `report.success` and the eight named checks.

5. **Point the panel lifecycle at a real broker.** Keep `check-host.sh`,
   and add a lane that loads the popout offscreen against `badi-broker
   --provider phrase` and checks pause, suggestion length and snooze in
   `badictl status`. Today's lifecycle speaks to a fake `badictl`.
